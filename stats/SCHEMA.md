# Bundle schema v1.0 (stats worker)

Python is the source of truth. `out/<claim_id>/bundle.json` is what the browser replays. Examples (synthetic, NOT real data):
`stats/fixtures/example_bundle.json` (validation placeholder passes everything) and `stats/fixtures/example_bundle_withheld.json` (no validation attached, so the verdict is withheld: the flag path).

Conventions: all numbers are plain JSON numbers rounded to 6 significant digits (cell fields 5); NaN is `null`; per-cell fields are flat arrays in row-major order (`index = iy * nx + ix`, `iy` along `lat`, `ix` along `lon`); slopes are per decade, in the variable's units per decade; years are calendar years.

## Input contract for the data worker (`data/<claim_id>/`)

`claim.json`:
```
{ "claim_id": "C-A", "claim_text": "...", "variable": "...", "variable_plain": "summer daytime land surface temperature",
  "units": "K", "direction": "increase" | "decrease", "season_months": [6,7,8], "period": [2001, 2025],
  "region_name": "the Southeastern United States", "region_box": {...},
  "product": {"name": "...", "version": "...", "doi": "..."}, "is_model_data": false }
```
`monthly.npz`: `values` (T, ny, nx) float, NaN = missing; `lat` (ny,), `lon` (nx,); `year` (T,) int; `month` (T,) int; optional `support` (ny, nx) bool (cells inside the region/land mask; default all). Months of the season only are needed (annual mean: all 12). Seasons must lie inside one calendar year. Aggregate to the shipped grid before writing (`trendtrial.aggregate.block_aggregate`: 0.05 to 0.25 degrees is k = 5). Run: `stats\.venv\Scripts\python -m trendtrial.pipeline data\C-A --out out\C-A --validation out\validation\validation_results.json`.

## Top level
`schema_version, run, claim, params, coverage, regional, sensitivity, cells, validation, verdict, finding, method_notes`.

- `run`: `run_id` ("run-" + 12 hex of sha256 over code version, input hashes, params, validation hash), `generated_at`, `code_version`, `seed`, `elapsed_seconds`, `input_sha256 {claim_json, monthly_npz}`, `software`.
- `claim`: claim.json copied verbatim.
- `params`: alpha 0.05, bh_q 0.10, cov_threshold 0.80, min_season_month_frac 2/3, min_clim_frac 0.6, min_valid_years_*, boot_reps 2000, boot_block_len 3, boot_level 0.95, seed, sensitivity grids, breadth_min 0.25, local_min 0.05.
- `coverage`: `n_cells_grid, n_support_cells, n_cells_with_climatology, cov_threshold, months_total, months_dropped, years_total, years_valid, years_dropped[], mean_valid_cell_frac, min_valid_cell_frac, monthly[{year, month, valid_cell_frac, area_weighted_frac, region_month_valid}]`.
- `regional`:
  - `years[]`, `anomaly[]` (area-weighted seasonal mean anomaly, `null` for invalid seasons), `valid_months[]`, `baseline_mean` (add to anomaly for an absolute-units display), `sen_line[]` (Sen line at each year), `units`, `season_months`.
  - `tests.mk_hr`: `n, s, tau, var_s_independent, hr_factor_raw, hr_factor` (floored at 1), `var_s, z, p, significant, alpha`. This is THE regional test.
  - `tests.mk_independent`: `z, p, significant` (same series, no autocorrelation correction; context).
  - `tests.sen`: `slope_per_decade, intercept, ci_bootstrap_per_decade [lo,hi]` (the interval to show), `ci_analytic_hr_per_decade` (context), `interval_method`.
  - `tests.ols`: familiar baseline: `slope_per_decade, se_per_decade, t, df, p, ci_per_decade, n, note`.
  - `band`: `years[], center[], lo[], hi[], level, meaning, reps, block_len, n`; same bootstrap draws as the slope interval; band is for the trend line, not individual years.
- `sensitivity`: `coverage[{cov_threshold, years_valid, p, slope_per_decade, significant_in_direction}]`, `block_len[{block_len, ci_per_decade, excludes_zero_in_direction}]`, `stable` (bool), `definition`. Label as sensitivity, not validation.
- `cells`: `grid {ny, nx, lat[], lon[], order}`, `n_valid_cells, n_excluded_cells, min_valid_years`, `fields` (flat arrays): `valid` (0/1), `slope_raw_per_decade` (rung 1 series), `slope_per_decade` (rungs 2-4), `p_rung1, p_rung2, p_rung3, bh_adjusted_p, hr_factor, flag_rung1..flag_rung4` (0/1). `rungs[4]`: `{rung, name, what_changes, flagged_cells, flagged_area_frac, flagged_in_direction_cells, flagged_in_direction_area_frac, cells_changed_vs_previous}`. `rung2_cells_with_changed_p` and `rung2_note`: if 0, say "rung 2 changed nothing here" (with complete months, anomalies only shift a cell's series by a constant). Area fractions are cos-lat weighted shares of valid cells, descriptive, never an error rate. Flags in the claimed direction only count cells whose Sen slope has the claimed sign.
- `validation`: `status` ("run" | "not_run"), `gate`, `claim_phi_hat`, `results_summary`, `results_run`, `source_sha256`. See "Gate flags".
- `verdict`: `id` (withheld | contradicted | supported | partly_supported | not_supported), `branch` (adds sub-branches `partly_regional_narrow`, `partly_local_only`), `text` (render this; the sentences come only from the fixed templates in `trendtrial/verdict.py`, no free text), `precedence_trace[]`, `withheld_reasons[]`, `inputs`, `branches[]`.

- `finding` (spec 3.8 card; every sentence is a fixed template, render as is): `place_name, variable, units, period, season, seasons_used, change_per_decade {value, units, interval [lo,hi] | null, interval_method, interval_meaning, scope}, product {name, version, doi}, verdict_id, verdict_text, not_supported[]` (what the evidence does not support), `selection_disclosure` (headline = the one pre-registered regional test; synthetic and user-exploration variants), `scope_text` (regional average vs hotspot), `is_model_data, run_id, ledger_ref`. `product` is copied from claim.json `product`; `ledger_ref` from claim.json `ledger_ref` if present, else "claim / run_id". `interval` is null when the gate disabled it. Extra optional claim.json keys used: `preregistered` (default true), `registration_ref`, `synthetic`, `ledger_ref`.
- Interval source: `regional.tests.sen.interval_used_per_decade` is the interval to show (null if disabled); `interval_method` says whether it is the bootstrap or the analytic Hamed-Rao interval (the gate picks: bootstrap if it passed its coverage bar, else analytic if that passed, else none). `regional.band` follows the same method (`band.meaning` states what it is).

## Addendum 2 fields (corrected tests, chosen by the validation gate)
- `regional.tests.shipped`: `{method, label, p, z, variance_factor, significant, alpha, selection}` is THE regional test whose p feeds the verdict (`null` if the gate disabled it). `method` is one of `mk_independent | hr_registered | hr_all_lags | yue_wang | tfpw | boot_mk_L3 | boot_mk_L5`. `tests.mk_hr` (registered Hamed-Rao) and `tests.mk_independent` stay as ladder context; show what each correction does.
- `cells.cell_test` (method used for rung 3 and as the BH input), `cells.cells_mode`: `bh_flags` (rung-4 flags are false-discovery controlled, measured on correlated synthetic fields) | `unadjusted_descriptive` (show cells with `flag_rung3` as UNADJUSTED and descriptive; make no false-discovery claim; the verdict does not use the map) | `off` (validation not attached). `cells.fields.p_rung3_hr_registered` keeps the registered Hamed-Rao p; `rungs[2]` carries `method`, `registered_hr_flagged_cells`, `registered_hr_flagged_area_frac`.
- `validation.gate` adds `regional_test`, `cell_test`, `cells_mode`, `candidate_table {method: {size, power, passes}}` (size at the governing null scenario, power at the governing trend scenario), `governing_n`, `governing_phi`. `validation.claim_phi_hat`, `claim_skewness`.
- Seasons that wrap the year (`claim.season_months` in season order, e.g. `[12,1,2]`): December comes from the previous calendar year, the season is labelled by the Jan-Feb year, the first season is dropped when its December is missing. Non-wrapping seasons may be given in any order.

## Verdict precedence (first match wins)
withheld > contradicted > supported > partly supported > not supported by this data. Definitions and the 0.25 / 0.05 thresholds are in `verdict.py` and were recorded in `event_record/STATS_LOG.md` before any claim data. Never present nonsignificance as unpublishable; never state a cause or forecast. The browser must render `verdict.text` as is.

## Gate flags (the browser MUST honour them)
`validation.gate`: `regional_verdict_enabled, interval_enabled, interval_method (bootstrap | analytic_hr | null), cells_enabled, reasons_blocking_verdict[], conservative_flags[], governing[]`.
- `regional_verdict_enabled = false`: show no regional verdict and no "significant / not significant" badge for the regional test; show `verdict.text` (withheld) and the reasons. Numbers may be shown as plain description only.
- `interval_enabled = false`: hide the slope interval and the chart band (the OLS interval is a baseline and may stay, labelled as such).
- `cells_enabled = false`: hide hotspot flags, flagged-area fractions and any breadth claim on the map; the per-cell p-values and slopes may still be shown as description.
- `conservative_flags`: show the text as a note near the verdict ("the test is conservative here: a non-significant result carries less weight"); it does not disable anything.
- Rules for how results become flags: STATS_LOG.md "WP3 validation design and PASS BARS". A claim is enabled only if all its governing scenarios pass.
- Independently, a claim whose regional series has fewer than max(10, 0.6 * seasons) valid seasons is withheld (G-Cov).

## Validation results file (`out/validation/validation_results.json`, run B merged with run A's interval results)
`run`, `scenarios[]`: regional scenarios `{id, n, phi, noise, gap_frac, trend_sd_per_decade, candidates {method: {size|power: {value, se, R}}}, size_checks {method: {passed, side (ok|liberal|conservative), band}}, interval {coverage_bootstrap, coverage_analytic_hr, sen_bias_sd_per_decade, checks {B3, B3a, B4}}, floor_ok}`; cell scenarios `{id, phi, truth, candidates {method: {cell_size, bh_fdr | p_any_bh_rejection, bh_power, B2_passed}}, floor_ok}`; `summary.failures[]` (all failed checks, published). Pass bars and selection rules: STATS_LOG.md ("WP3 validation design and PASS BARS" and "WP0 METHOD ADDENDUM 2"). Run A alone (registered method only) is `validation_runA_registered_method.json`; the candidate run is `validation_B.json`.

## Honest limits to print
Hamed-Rao is less reliable for short series; gaps are skipped (lags counted in valid observations); BH wording per spec 3.5; synthetic calibration does not establish BH validity for all real fields; field significance out of scope; hotspot intervals pointwise.

## JS series-level module (Detective mode): `stats/js/trendtrial.js`
Dependency-free ES module (`import {...} from "./trendtrial.js"`). It ports only SERIES-level functions of the Python core and is checked against it (`tests/test_js_parity.py`, 240 series + 40 seasonal sets + 12 verdict inputs). Per-cell maps, BH and the bootstrap stay Python-only (case files).
- `olsTest(t, y)` -> `{n, slope, se, t, df, p, ciLow, ciHigh}` (slope per unit of t; multiply by 10 for per decade).
- `mannKendall(y, t, {corr: "hr"})` (`corr` = `none | hr | hr_all | yw | tfpw`; legacy `{hr: false}` = none) -> `{n, s, tau, varS0, hrFactorRaw, hrFactor, varS, z, p, slope, intercept}`; ties corrected; Hamed-Rao factor floored at 1; gaps (null/NaN) skipped, Sen uses calendar differences.
- `senInterval(y, t, varS)` -> `[lo, hi]` analytic Gilbert interval (pass the Hamed-Rao `varS`). In Detective mode this is exploratory and not validated for the user's series.
- `seasonalSeries(rows, {months, y0, y1})` with `rows = [{year, month, value}]` -> `{years, raw, anomaly, nMonths}`; anomaly = mean of (value minus that calendar month's mean over y0..y1) over the same months as `raw`; a season needs at least ceil(2/3 * months) usable months; a month needs 60 percent of years for its climatology.
- `analyzeSeries(t, y, {units, corr = "yw"})` -> `{ols, mk, mkIndependent, mkRegistered, sen, verdict}` in one call (`mk` uses the default Yue-Wang correction, the best-calibrated in validation run B; `mk.correctionName/correctionNote` name it for the trial table; `LADDER_STEPS` and `CORRECTIONS` are exported); `detectiveVerdict(p, slope, n, units)` -> `{id, text}` with ids `significant_up | significant_down | not_significant | too_short`.
- Wording (the challenge author's framing, fixed templates): p < 0.05 is statistically significant; "A p-value above 0.05 does not mean there is no trend or that it is unimportant, and a longer series can help." Significant text says it does not explain why or what comes next. Render `verdict.text` as is.
- Label every Detective result "your own exploration, not pre-registered"; the Detective verdict is NOT gated by the case-file calibration (no validation has been run for user-chosen series), so always show the persistence caveat from `method_notes`: p-values here are typically too small when a series has year-to-year persistence.

## Round 2 changes (schema 1.1; STATS_LOG "ROUND 2")
**Interval fields moved so the rejected one cannot be shown by accident.** `regional.tests.sen` no longer has `ci_bootstrap_per_decade`, `ci_analytic_hr_per_decade`, `interval_used_per_decade` or `interval_method`. Use:
- `regional.interval.selected` = `null` (nothing may be shown) or `{method (bootstrap | analytic_hr), method_label, low, high (per decade), level_nominal (0.95), level_text, coverage_achieved {headline {value, se, R, source}, fixed_persistence_by_scenario, adaptive_procedure {interval_coverage_null, interval_coverage_trend}, bar, nominal}, meaning, band_meaning}`. `headline.value` is the share of synthetic series whose true slope this interval contained (state it next to the nominal 95%).
- `regional.interval.candidates.{bootstrap, analytic_hr, ols}` = `{method, method_label, low, high, passed_coverage_bar, selected, coverage_by_scenario, status}`. For audit only; never display a candidate whose `selected` is false as the interval (the OLS interval may be shown only as the labelled baseline).
- `regional.interval.disabled_reasons[]`, `selection_rule`, `warning`.
- `regional.band` (selected method only, `null` when no interval is selected) now has `band_meaning`, a plain sentence (slope-range band: a band for the trend line, not for individual years). `finding.change_per_decade.interval` is the selected `[low, high]` (or `null`) and `interval_method` its label.
**Cells.** `cells.rungs[]` add, besides the old fields: `cells_tested`, `flagged_cell_share` (flagged cells / tested cells), `flagged_area_share` (cos-latitude weighted share of tested area), `flagged_in_direction_cell_share`, `flagged_in_direction_area_share`, `p_threshold` (rungs 1-3: 0.05, unadjusted two-sided) or `q` (rung 4: 0.10) with `effective_raw_p_cutoff`, `threshold_text`, `explain` (rung 4: why it can flag more cells than rung 3), `share_note`. Old `flagged_area_frac` and `flagged_in_direction_area_frac` are area shares (not cell shares). `cells.q`, `cells.alpha_cell`, `cells.n_native_cells`, `cells.agg_k` (the cell ladder and map use block-aggregated cells when the native grid has more than 10,000 cells, k = 5; the REGIONAL series always uses native cells); `coverage.n_native_cells`, `coverage.cell_agg_k`; `params.cell_agg_k`.
**Validation.** `validation.adaptive` (also `validation.gate.adaptive`) = the whole adaptive procedure (estimate persistence, pick scenario and test, test, interval) checked on held-out synthetic series at this claim's cell: `{status, cell, n, true_phi, size_unconditional, release_rate, size_given_release, power_unconditional, power_given_release, interval_coverage_null, interval_coverage_trend, interval_shown_rate, selected_share, buckets, bars {AP1, AP3}}`. AP1 failing withholds the regional verdict; AP3 failing disables the interval. `gate.adaptive_notes[]` (show when present: the release-conditional false-positive rate is above 5%), `gate.reasons_interval[]`, `gate.interval_table`, `gate.cell_family`, `gate.cell_table {candidate: {homogeneous_passes, heterogeneous_passes, bh_power}}` (cells_mode needs both).
**finding.selection_disclosure** now states that the shipped test was chosen by the pre-declared rule (addendum 2) on simulated data, with raw Mann-Kendall and the registered Hamed-Rao shown as context.

## Exploratory gate (Detective): `exploratoryGate(t, y, {period})` in `js/trendtrial.js` (1.3.0), `trendtrial.exploratory.exploratory_gate(y, t, period)` in Python
Returns `{phiHat, skew, nValid, hasGaps, nGov, phiGov, correction ("yw"), correctionName, sizeAtBucket {size, se, power, adaptiveSize, adaptiveRelease} | null, calibrated, reasons[], caveat, label}`. `calibrated` is true only if the Yue-Wang test's size at the (n, persistence) bucket is within 0.05 + 2 SE in the shipped table, the series has no gaps, |skew| <= 0.8, 20 to 50 valid points and persistence <= 0.6. Always render `caveat` and `label` ("your own exploration, not pre-registered") next to a Detective p-value; when `calibrated` is false do not describe the result as validated. The table (`GATE_TABLE`, also `trendtrial/gate_table.json`) is generated by `scripts/make_gate_table.py` from the validation results; Python/JS parity is tested.

## Round 3 additions (STATS_LOG R3-1 to R3-8)
- `run`: `run_id` is now "run-" + 12 hex of sha256 over the content of the code (`code_sha256`, from `code_files[{path, sha256}]`: every .py and .json in `stats/trendtrial`, CRLF normalised), the input hashes, the params and the validation file hash (`id_rule` says so). `supersedes[]` lists earlier run ids of the same claim from `stats/run_id_history.json` (`{run_id, generated_at, round, verdict, status: "superseded", reason}`); those ids hashed a version string and cannot be recomputed. `code_version` is only a label.
- `coverage.years_absent[]`: years of the requested period for which the data file has no month of the season at all (a subset of `years_dropped`). A series with any missing year has `has_gaps` and its claim verdict is withheld (no validated gap path); the gate reason starts with "N of the M seasons ... have no valid regional value".
- `validation.gate`: `governing_buckets[]` (primary first; a negative phi_hat is bracketed by two tested values), `bucket_rule` (plain text), `skew_scenarios` (matched | legacy | null), `withheld_driver` (skew | dependence | gaps | combinations | none), `reasons_blocking_verdict[0]` is generated from the scenarios that failed. `adaptive.noise` = normal | skewed (the skewed adaptive cell governs a claim with |skew| > 0.8).
- `validation.display` (R3-6): `{status, setting_text, adaptive_cell, noise, interval_text | null, interval_coverage_null/trend {value, se, R}, false_positive_text | null, false_positive_released {value, se, R}, false_positive_overall, release_rate, false_positive_definition, applies_to_this_claim_verdict}`. Show the two texts as given.
- Exploratory gate: result gains `missingYears`, `nExpected`, `phiBuckets`; `exploratoryGate(t, y, {period: [y0, y1]})` counts years absent at either end; a series with any missing year is `hasGaps` and not `calibrated`.
- Validation file: negative-persistence regional scenarios (phi -0.7, -0.5, -0.3), skewed-noise nulls `R-null-skewed-n{n}-phi{phi}` for the full grid, cell families CB/CD at negative g and CD2 (real C-D grid, 6 x 7) at every g, and adaptive cells `n{n}-phi{phi}` (normal) and `n{n}-phi{phi}-skewed` re-run with the round-3 gate (seed family 2027). The round-2 file is `validation_results_round2.json`.
